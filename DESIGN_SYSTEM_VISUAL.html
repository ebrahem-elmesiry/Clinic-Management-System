8. How to build a new page (plain-English rules)

From the 16-point Reuse Guide in DESIGN_SYSTEM.md.

  • Shell: wrap the page in p-8 space-y-6 (add max-w-7xl mx-auto for patient pages).
  • Cards: white, 12px radius, thin gray border, shadow-sm, p-6 body.
  • Page header: big title left, action buttons right.
  • Buttons: use the shared Button; override to bg-blue-600 for primary, variant="outline" for secondary.
  • Badges: pill = bg-{color}-100 text-{color}-700. Green=success, orange=warning, blue=info, red=error, gray=neutral.
  • Forms: shadcn Input/Label/Select/Dialog. Fields stack in space-y-4, two columns via grid-cols-2.
  • Gradients: blue→teal is the only brand color moment. Use it for logos, avatars, hero banners, summary cards.
  • Icons: lucide-react only, stroke style, sized w-4 to w-6.
  • Don’t add: new fonts, new colors, new radius/shadow scales, or new component libraries.

9. Known quirks (left as-is)

Documented in DESIGN_SYSTEM.md §18 — not bugs to fix right now, just things to know.

  • Two color systems: the CSS token --primary is near-black, but the app visually uses blue-600. Blue is what you see.
  • Dark mode isn’t wired up: dark theme values exist in CSS but nothing ever switches to them — the app is light-mode only.
  • Duplicated CSS files: four theme files hold the same tokens.
  • Mixed form fields: some pages use shadcn inputs (gray fill, 6px corners), others use raw HTML inputs (white fill, 8px corners). Both appear.
  • One broken class: Doctor Dashboard status dots use a dynamic class name Tailwind can’t build — they render without color.
  • ~38 unused components: Badge, Card, Avatar, Table, etc. exist in the codebase but are never imported; the pages hand-roll those patterns instead.
